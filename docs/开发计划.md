# 三国富甲天下（Web 版）开发计划

## 一、背景与目标（Context）

- 工作目录 `f:\Github\sanguo16` 当前**完全为空**，本项目从零开始。
- 目标：仿照台湾光谱资讯《富甲天下2》——三国题材的「大富翁 + 模拟经营」棋类游戏，做一款**浏览器直接可玩**的中文 Web 游戏。
- 从公开资料确认的《富甲天下2》核心机制（作为还原依据）：
  - 转盘点数走格，最多 4 人同乐（刘备 / 曹操 / 孙权 / 董卓，另有公孙瓒），其余由 AI 接管。
  - 走到城池可占领；占领后可**派一员大将带兵镇守**。
  - 敌方路过你的城池必须**交税**，或选择**宣战**（交战）；己方战胜则对方免/减税，战败则付双倍。
  - **招贤馆**招募名将需花钱，且招募看「合不合得来」（**相性**匹配），如刘备易得诸葛亮。
  - 三种战斗模式：**单挑、野战、攻城战**。
  - 城池建设系统：**市集、农田、练兵场、护城河**等设施，分别提升经济与防御。
  - 剧本分幕：**黄巾之乱 / 群雄割据 / 一统中原 / 富甲天下**。
- 交付形态：双击 `index.html` 即可开局；无后端、无构建工具；存档存 `localStorage`。
- 三方库：仅 three.js（UMD 构建，随仓库内置在 `js/lib/three.min.js`；现代版只发 ES Module，`file://` 下会被 CORS 拦，故取旧版 UMD）。

## 二、技术方案与关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 渲染 | **DOM + CSS 为主，SVG 垫底**；棋盘另可选 **three.js WebGL 三维层** | 格子约 40 个，DOM 足够；hover 提示、事件绑定、devtools 调试都方便；棋子移动用 `transform + transition` 做动画。3D 视角下只有棋盘几何体进 WebGL（底座、40 个立体格子、棋子令牌，以及外环以内纯代码生成的**地形沙盘**：山脊折线叠高斯出山脉、碗形凹陷压低出江东水域、河床下切出黄河，顶点色按海拔与地域取色），中央面板 / 弹窗 / 提示仍是 DOM 覆层；`board.js` 与 `render3d.js` 接口一致，由 `main.js` 按视角路由，逻辑层零改动，WebGL 不可用时自动回落 2D。 |
| 脚本组织 | **多个 classic `<script>` + 全局命名空间 `SG`** | `file://` 协议下 ES Module 与 `fetch` 都会被 CORS 拦截。为满足「双击即玩」，必须用非模块脚本；所有数据表写成 `.js` 常量而非 `.json`。 |
| 数据 | 数据驱动，表与逻辑分离 | 城池 / 武将 / 卡片均为独立数据文件，方便加内容与调平衡。 |
| 存档 | `localStorage` + `try/catch` 内存兜底 | 部分浏览器在 `file://` 下会限制存储；失败时降级为内存态，并提供「导出 / 导入 JSON」按钮兜底。 |
| 美术 | CSS / SVG / emoji 自绘为主 | 零外部素材依赖，保证离线可玩；武将头像在 P4 用图片生成接口补充。 |
| 编码 | 全部 UTF-8，`<meta charset="utf-8">` | 避免中文乱码。 |

## 三、玩法设计

### 3.1 棋盘
- 环形闭合路径，约 **40 格**，用百分比坐标布局在 `aspect-ratio:1` 的容器里，天然响应式。
- 格子类型：`start`（起点/过关领俸）、`city`（城池，可占领）、`pass`（关隘，过路收费点）、`event`（事件抽卡）、`tavern`（招贤馆）、`farm`（农田资源点）、`chance`（机会）。
- 城池按地域分组（中原 / 江东 / 巴蜀 / 河北），同地域连片占领有**联片加成**。

### 3.2 势力与资源
- 可选势力 4 个：**刘备 / 曹操 / 孙权 / 董卓**，各含初始金、粮、兵力、初始城池、初始武将、势力特性（如刘备「仁德」招募成本低、曹操「屯田」粮产高）。
- 三种资源：**金**（买地/招募/建设）、**粮**（养兵，每回合按兵力扣）、**兵力**（战斗与守城）。

### 3.3 城池与建设
- 城池有等级 1–5，收益随等级提升；建设成本按 `baseCost * level^1.8` 递增，防止无脑升级与金钱通胀。
- 建筑槽（每城最多 4 个）：**市集**（+金）、**农田**（+粮）、**练兵场**（+兵力/防御）、**护城河**（+守城防御）。
- 驻守：可派遣 1 名武将 + 一定兵力驻城，直接影响被攻时的防御力。

### 3.4 武将
- 属性：`武力 / 智力 / 统率 / 相性 / 俸禄`。
- 相性（0–100）决定招募难度与忠诚，影响「招贤馆」能否招到（还原原作的「合得来」机制）。
- 驻守武将在攻城战、单挑中提供直接战力。

### 3.5 战斗（还原三种模式）
- **单挑**：双方驻守/随行武将按 `武力 + 随机` 对决，胜者提振全军士气（战力加成）。
- **野战**：攻守双方 `兵力 × 统率` 加随机与士气比较。
- **攻城战**：守方获得城池等级 + 练兵场 + 护城河的防御加成。
- 结算产出 `BattleResult`（各回合过程、胜方、掠夺的金/粮、城池易主），并输出到战斗日志与动画。

### 3.6 事件卡（机会 / 命运）
- 表驱动，带 `effect`：加/减金粮、强制移动、免费过路、天灾损兵、招贤折扣、敌军突袭等，约 30–40 张。

### 3.7 胜负判定
- **统一**：某势力占领全部城池。
- **富甲天下**：达到设定的回合上限时，按「总资产 = 金 + 城池估值 + 兵力估值」最高者获胜。
- 破产（金 < 0 且无地可卖）出局。

## 六、回合状态机

- 阶段枚举：`TURN_START → ROLL → MOVE → LAND → ACTION → END → GAME_OVER`。
- 流转：
  - `TURN_START`：结算己方城池收益、扣兵力粮草、判定破产。
  - `ROLL`：骰子动画（约 300ms）。
  - `MOVE`：逐格步进动画（每格约 120ms），路过起点领俸。
  - `LAND`：按格类型结算（空地可买 / 己城可升级 / 敌城「交税 or 宣战」/ 事件抽卡 / 招贤馆招募）。
  - `ACTION`：玩家自由行动（招募、建设、出兵、交易），可多次，手动结束。
  - `END`：切换 `currentFactionId`，满一圈 `round++`，检查胜负。
- **人机统一**：引擎只调用 `await waitFor(decision)`。人类由 UI 的 Promise 喂入，AI 由 `ai.js` 延时约 200ms 喂入——引擎不区分人机，规则不写在渲染层。
- **防竞态**：全局 `busy` 锁 + Promise 动作队列，动画播完才结算，杜绝连点导致的状态错乱。

## 七、AI 决策（可解释、易调参）

按优先级打分，参数集中在 `SG.AI.PARAMS`（`reserveGold`、`buyScoreMin`、`upgradeBias`、`warRatio` 等），并加 ±15% 随机抖动避免机械感：

1. **保命**：金不足以付过路费时优先卖地 / 放弃交战。
2. **买地**：`gold > price + reserveGold` 且「收益/价格」比超过阈值才买。
3. **升级**：优先升级对手必经的高密度节点城。
4. **招募**：`value = war*2 + intel + affinity*1.5`，且 `gold > salary*5` 才招。
5. **出兵**：己方战力 > 目标 ×`warRatio`(默认 1.3) 且目标价值高时才宣战。

## 九、验证方式

1. **启动验证**：双击 `index.html`（`file://` 协议）能正常加载，无 CORS/乱码报错；再在 `http://localhost` 下复测一次。
2. **功能验证**：按 P1→P4 逐阶段用浏览器实机走一遍——掷骰移动、买地、升级、招募、宣战、三种战斗、事件卡、存读档、胜利结算。
3. **规则验证**：构造已知参数的测试局面核对算法语义（如攻城战力公式、过路费 = 城池收益 × 倍率）。
4. **竞态验证**：连续快速点击骰子/按钮，确认 `busy` 锁生效、状态不错乱。
5. **存档验证**：刷新页面后读档一致；导出 JSON 再导入结果一致。
